# Security policy

## Reporting a vulnerability

Use **Security → Advisories → Report a vulnerability** on this repository when
private vulnerability reporting is enabled. Do not post exploit files, credentials,
or private project data in public issues. If the private-report control is absent,
ask the maintainer to establish a private channel before sending sensitive details.

Include the affected release/commit, browser, minimal reproduction and impact.
For an import/export issue, describe the route and attach only a synthetic example.
Avoid testing with other people's data or disrupting the public service. This
project does not promise a response time or operate a bug-bounty program.

## Support and trust boundaries

Security fixes target the current maintained release. Older tags are retained for
scientific reproducibility and do not imply ongoing security support. Dependency
audits run in CI and weekly checks; a previously passing audit is not a permanent
security assurance. The live website and an archived research release can differ.

Graph computation and project storage run in the browser. The site has no graph
upload API or account service. Browser storage and downloaded files can contain
your own research data; keep backups and avoid sharing sensitive files in reports.
The hosting provider still receives ordinary requests for the site and assets.

Production headers are configured in `public/_headers`. They apply to static
asset responses, not necessarily redirects/errors generated by Cloudflare before
asset handling. CSP does not protect a downloaded SVG opened outside the app;
input validation and export escaping remain required. Source maps, secrets and
private review material must not be included in a deployment or source release.

CI has read-only repository permissions and does not deploy the website. Local
`npm run deploy` is a separate privileged operation using the maintainer's
Cloudflare authentication; contributors do not need those credentials to test.
