# Reproducible polyhedron templates

All 20 fixed templates are generated by this project's code, from geometric
definitions. No downloaded coordinate/face tables, former catalog, network
request, or geometry package is an input. The generated catalog and construction
code are covered by the project's Apache-2.0 source license.

```sh
npm run bake        # regenerate both catalogs
npm run bake:check  # compare with checked-in catalogs without writing
```

`npm run check` includes the second command. Node 22 is the reference toolchain;
the check compares serialized values rounded to ten decimal places. This is not
a promise of bitwise floating-point reproducibility on every future engine.
Oriented faces start at their smallest vertex ID and sort by length, then by
vertex IDs. This removes the platform-dependent cyclic start at atan2's ±π cut
without reversing face winding, and makes the Tutte boundary choice deterministic.

## Construction methods

The six elementary solids in `scripts/generate-templates.mjs` use sign changes
and cyclic coordinate permutations: tetrahedron, cube, octahedron, dodecahedron,
icosahedron, and rhombic dodecahedron. The golden ratio is computed as
φ = (1 + √5)/2. The rhombic dodecahedron uses the eight cube corners (±1,±1,±1)
and six axis points (±2,0,0), (0,±2,0), (0,0,±2); its faces are rhombi, not squares.

The remaining constructions are in `scripts/polyhedra.mjs`. The general
reflection-orbit method is described by G. C. Shephard,
[A Construction for Wythoffian Polytopes](https://doi.org/10.4153/CJM-1954-015-5)
(1954). Rotational-orbit constructions of the snub solids are discussed by
M. Koca, N. O. Koca and M. Al-Shu'eili,
[Chiral Polyhedra Derived From Coxeter Diagrams and Quaternions](https://arxiv.org/abs/1006.3149)
(2011). These are mathematical references; no coordinate tables, implementation,
figures or text from them are bundled. The formulas below specify our conventions
and derive the inputs used by our implementation.

### Reflection orbits

For p = 3, 4 or 5 put c = cos(π/p), s = sin(π/p), and choose unit normals

```
n0 = (1, 0, 0)
n1 = (-c, s, 0)
n2 = (0, -1/(2s), sqrt(1 - 1/(4s²)))
ri(x) = x - 2(ni·x)ni
```

Their pairwise inner products are −cos(π/p), −1/2 and 0. They generate the
finite Coxeter groups [p,3] of orders 24, 48 and 120 respectively. For a set of
active mirrors A, solve the triangular system ni·x = 1 if i∈A, and 0 otherwise.
Reflect x repeatedly in all three mirrors until its orbit closes. Active-mirror
edges have length 2 before final normalization. The following table is sensitive
to this numbering convention; swapping the end mirrors exchanges dual roles.

| Solid | p | Active mirrors |
| --- | --- | --- |
| Truncated tetrahedron | 3 | 0,1 |
| Cuboctahedron | 4 | 1 |
| Truncated cube | 4 | 0,1 |
| Truncated octahedron | 4 | 1,2 |
| Rhombicuboctahedron | 4 | 0,2 |
| Truncated cuboctahedron | 4 | 0,1,2 |
| Icosidodecahedron | 5 | 1 |
| Truncated dodecahedron | 5 | 0,1 |
| Truncated icosahedron | 5 | 1,2 |
| Rhombicosidodecahedron | 5 | 0,2 |
| Truncated icosidodecahedron | 5 | 0,1,2 |

### Snub cube and snub dodecahedron

Use the same mirrors with p=4 and p=5 respectively, but take only the proper
rotations r0r1, r1r2 and r0r2. With ui=ni·x and ni·nj=−cij, direct expansion gives

```
|x − ri rj x|² / 4 = ui² + uj² + 2 cij ui uj.
```

Set u1=1, u2=t, u0=√(1+t). Equality of the three rotation-edge lengths reduces to

```
(t−1)²(t+1) = 4 cos²(π/p),   1 < t < 3.
```

The left side is strictly increasing on (1,3), and brackets the right side.
Bisection for 60 iterations determines the root to floating-point accuracy;
this avoids importing a decimal constant. Solve ni·x=ui and enumerate its
rotation orbit: 24 vertices for the snub cube, 60 for the snub dodecahedron.
The inverses of r0r1 and r1r2 supply two additional neighbors; r0r2 has order 2,
so there are five neighbors at the common edge length. The generated convex hull
is checked for regular faces and the correct face inventory. One handedness is
chosen consistently; no identity with the old catalog's handedness is claimed.
Reflection changes handedness but not the unweighted graph or its curvature.

### Elongated square gyrobicupola (J37)

Start with a unit-edge regular octagonal prism. Its two rings have z=±1/2,
radius R=1/(2sin(π/8)), and angles π/8+kπ/4, k=0,…,7. Add square caps with radius
r=1/√2 and heights z=±(1/2+r). The bottom square has angles π/4+kπ/2; the top
has kπ/2. Thus the cupolae are rotated by π/4 relative to each other.

Square edges and vertical prism edges have length 1. For a cap vertex and its
two adjacent ring vertices, the horizontal distance is 1/√2 and the vertical
distance is 1/√2, so these edges also have length 1. The convex hull has eight
triangles and eighteen squares. Using the same cap angle on both ends would
instead produce the rhombicuboctahedron; counts alone cannot distinguish them.
The two graphs' different curvature spectra are checked separately.

## Faces, layout and validation

All coordinates are normalized to unit shortest pairwise distance. Edges join
points at that distance. Supporting planes of triples identify convex faces;
coplanar vertices are angle-ordered with outward normals. A Tutte embedding
places the largest face on a circle, solves the interior barycentric equations,
and scales the median 2D edge length to 64 layout units. No previous layout or
vertex/face numbering is reused for the 14 replaced templates.

Checks cover vertex/edge counts and degrees, Euler characteristic, expected
face sizes/counts, unit edge lengths, face planarity, regular polygon angles
(except the Catalan rhombi), convex support planes, two oppositely oriented
incident faces per edge, and 2D separation/noncrossing. J37 and the
rhombicuboctahedron also retain distinct numerical curvature regression spectra.
These are numerical implementation checks, not a formally verified convex-hull
algorithm. Generation runs at development time; no new runtime geometry cost
or dependency is added to the web app.

After building, `npm run qa:templates` uses a dedicated production-preview
server and an isolated Chromium profile to place all 20 templates through the
UI, check the resulting graph and finite Worker results, download 2D SVGs, and
verify projected vertices and nonblank downloaded 3D PNGs. WebGL is required;
this suite does not count a fallback as a successful geometry check. It is not
a physical-GPU benchmark or a proof of label readability on every display.

## Templates and saved projects

Saved projects contain their own vertices, edges and positions. Regenerating the
template catalog does not rewrite saved projects. User-import support for the
documented polyhedron text format does not bundle any external coordinate table.
